# 学习笔记 09：流式滤波与 C 环形缓冲

对应 Python 的 `FirFilter`、`IirFilter`，以及 C 的 `fir_create`、`fir_process`、`fir_destroy`。

## 分块不能改变滤波结果

同一个输入可以一次送入，也可以切成 1、7、64、512 点的小块。块边界只是传输安排，不是信号重新开始的位置。

FIR 有 N 个系数，计算当前输出需要当前输入和最近 N−1 个历史输入。上一块太短时，所需历史会跨越多个块。例如五个系数，已处理 `[2,5,1]`、`[7,3,8]` 后，应保留最近四项 `[1,7,3,8]`。

## Python 对象保存状态

`__init__` 在创建对象时初始化数据。`self` 表示当前对象，`self.buffer` 与 `self.write_index` 在多次调用之间保留。

```python
fir = FirFilter(h)
first = fir.process(block1)
second = fir.process(block2)
```

两个调用使用同一个对象，所以第二块能继续使用第一块的历史。`outputs=[]` 是本次调用的局部结果列表，每次重新创建是正确的；不能在每次 `process` 开始时清零历史。

不同实例各自拥有缓冲区。构造时复制调用方的系数，避免外部数组后来被修改而改变已有滤波器。

## 环形缓冲怎样对应时间

缓冲区开 N 个位置，容纳当前输入与 N−1 个历史输入。每来一个样本，就覆盖最旧的位置。

假设缓冲区为 `[7,5,1]`，当前写入位置是 0，时间顺序是当前 7、上一项 1、再上一项 5。

| 变量 | 职责 |
|---|---|
| i | 当前块中正在处理哪个输入，生成哪个输出 |
| write_index | 当前输入放在哪个物理格子 |
| k | 正在使用第几个系数，也表示向过去找几步 |
| index | 对应历史样本实际存在哪个格子 |

Python 使用 `index=(write_index-k)%N`，再累加 `h[k]*buffer[index]`。每个新输入都重新把 total 设为零，遍历全部系数后输出一个样本。

C 的负数余数规则不同：Python 中 `-1%3=2`，C 中 `-1%3=-1`。当前 C 实现先做 `index=write_index-k`，若负数则加 N。由于 k 在 0 到 N−1 之间，加一次即可绕回。

## IIR 多保存输出历史

$$
y[n]=\sum_{k=0}^{M}b[k]x[n-k]-\sum_{k=1}^{N}a[k]y[n-k]
$$

上式假定 `a[0]=1`。反馈循环从 k=1 开始，只读取已经算出的输出。当前输出算完后再写入输出缓冲区。

输入、输出环形缓冲分别按自身长度绕回，不能把输出索引对输入缓冲长度取模。分子与分母等长时，这个错误容易被掩盖，因此测试包含不等长情况。

一般 a[0] 不为 1 时，把 b、a 同时除以原来的 a[0]。a[0]=0 必须拒绝。非法输入块在进入处理循环前整体检查，避免处理了一半才报错、破坏历史状态。

## C 中的对象与内存

`typedef struct fir_state fir_state_t;` 声明状态类型并起别名。具体字段在 `fir.c` 定义，调用方通过状态指针使用接口。

```text
fir_state_t *s
  ├── h：系数数组地址
  ├── buffer：环形缓冲数组地址
  ├── nh：系数数量
  └── write_index：当前写入位置
```

结构体变量通过点号访问，结构体指针通过箭头访问。`s->nh` 是整数数量，`s->h` 是数组地址；malloc 返回的地址不能写入 `s->nh`。

`fir_create` 申请结构体、申请系数数组、申请清零缓冲区，并复制系数。申请失败时释放此前成功申请的内存。`fir_process` 只使用已有状态，不在处理循环中申请内存。`fir_destroy` 先释放两个数组，再释放结构体。

C 把输出写入调用方准备好的 `out` 数组，所以处理函数返回 `void`，并不表示没有计算结果。

## 验收依据

| 验收项 | 要求 |
|---|---|
| Python vs SciPy lfilter | 逐样本绝对误差小于 1e-10 |
| Python 不同分块 | 与整段处理逐点完全一致 |
| C float vs Python 双精度参考 | 逐样本绝对误差小于 1e-6 |
| C 不同分块 | 与 C 整段处理逐点完全一致 |

C 对拍先把固定系数、输入保存为 float32 `.npy`。参考输出使用这些相同数据转为 float64 后计算。测试读取文件，通过 ctypes 传给真实编译出的 C 库；C 不再另生成一套随机输入。

CTest 中注册一个 `fir_golden` 测试，内部执行 21 个 pytest 用例。普通 Python 回归没有提供 C 库路径时，会跳过这 21 项；需要另外运行 CTest。

“No tests were found”说明尚未发现注册测试，不表示验收通过。本轮实际遇到的原因是 CMakeLists 修改后未保存。保存后重新配置、编译，再用 `ctest -N` 检查注册结果。

## 与居中卷积区分

`myconv(..., mode="same")` 按 NumPy 约定居中截取；当输入更长、滤波器为奇数长度时，相当于补偿了该对称 FIR 的整数样本延迟。

流式处理按因果顺序即时输出，保留滤波器延迟，验收应与 `lfilter` 比较。不能把这两种不同时间对齐方式的结果直接相减，作为误差结论。
