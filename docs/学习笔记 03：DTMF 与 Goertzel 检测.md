# 学习笔记 03：DTMF 与 Goertzel 检测

> 对应代码：`dsp-toolbox/dsp_toolbox/dtmf.py`、`examples/demo_dtmf.py`、`tests/test_dtmf.py`。

## 1. 一次按键为什么有两个频率

DTMF 键盘有四行、四列。每行一个低频（697、770、852、941 Hz），每列一个高频（1209、1336、1477、1633 Hz）。按键音是对应行、列两个正弦波之和。例如数字 **5** 位于第二行第二列，因此主要包含 **770 Hz 和 1336 Hz**。

```text
             1209   1336   1477   1633 Hz
697 Hz         1      2      3      A
770 Hz         4      5      6      B
852 Hz         7      8      9      C
941 Hz         *      0      #      D
```

识别一个键，就是分别在低频组和高频组找到最可信的频率，再用行、列查表。只找到一个强频率还不够：噪声也可能在某个频点碰巧很强。

## 2. 为什么要同时乘正弦和余弦

想判断信号 `x[n]` 里有没有频率 `f`，可以把它分别乘以该频率的正弦和余弦，再对所有样本求和：

```text
S = Σ x[n] sin(2πfn/sr)
C = Σ x[n] cos(2πfn/sr)
强度 = √(S² + C²)
```

这里 `n/sr` 是第 `n` 个样本的时间。正弦和余弦相差 90°，二者合起来能覆盖未知的起始相位。若只乘正弦，某些相位的真实按键音可能被误判为很弱。

强度只是这段音频中该频率的**原始求和幅度**，会随样本数和音量变化；不能把它直接当成 0～1 的概率。

## 3. Goertzel 为什么有用

FFT 会算一整排频点；DTMF 只关心八个指定频率。Goertzel 用一个两步递推来计算某个频率的强度，不必先算完整频谱：

```text
a = 2 cos(2πf/sr)
s[n] = x[n] + a·s[n−1] − s[n−2]
强度² = s_last² + s_prev² − a·s_last·s_prev
```

程序里 `previous1` 和 `previous2` 分别保存最近两次递推结果。每读一个样本，就计算 `current`，然后把两个旧值往后挪。最后用上式得到与“正弦、余弦直接求和”相同的强度；`max(power, 0.0)` 是为了防止浮点舍入把接近零的值算成很小的负数。测试用独立的直接求和方法核对了八个 DTMF 频率以及一个非整数频率。

## 4. 从强度到按键：三道门

`detect_key(x, sr)` 先检查输入，再依次判断：

1. **音量门**：均方根 `RMS = √mean(x²)` 低于 `min_rms` 就返回 `None`，避免把静音当按键。
2. **突出程度门**：低频组和高频组都比较“第一名 ÷ 第二名”；若任一组小于 `min_ratio`，就返回 `None`。`peak_ratio` 做的正是这一步。
3. **双音存在门**：取两个获胜频率中较弱的那个，除以 `样本数 × RMS`；若低于 `min_concentration`，就返回 `None`。这样可以挡掉“只有一组频率比较突出”的输入。

三道门都通过后，才把最强低频映射成行、最强高频映射成列，从 `KEYPAD[row][col]` 得到字符。阈值是针对当前演示和合成测试设的经验值，真实录音还需重新验证。

## 5. 怎样识别连续按键

`detect_dtmf(path)` 先用 `wave` 读取 WAV，再把音频切成约 **40 ms** 的短窗，每隔 **10 ms** 检测一次。窗口会重叠，所以一个 120 ms 按键会被看见多次。程序把相邻窗口里同一个标签合并成一次按键，并忽略短暂的一帧空白；连续两个空白窗口才结束该键。这样能从演示音频得到 `13800138000`，包括重复的 `0`。

运行演示时，先在 `dsp-toolbox/` 目录执行：

```bash
python examples/demo_dtmf.py
python -m dsp_toolbox.dtmf samples/dtmf_demo.wav
```

第一条命令生成音频并识别；第二条命令演示真实文件入口。直接运行 `python dsp_toolbox/dtmf.py` 没有传入文件路径时，命令行会提示缺少 `path`，这是参数检查在起作用。

## 6. 测试证实了什么，尚未证实什么

`tests/test_dtmf.py` 检查了单键、16 键 × 20/10/0 dB 三档**合成噪声**、重复键序列、静音、纯噪声、非法输入和命令行读取。这证明当前实现通过了这些可重复的人工样本，**不等于**在任意电话录音里也能达到 100% 准确率。

目前的 WAV 读取只接受未压缩 **16-bit PCM**。立体声会平均成单声道，若两声道相位相反就可能抵消。重复按键也需要足够的静音间隔才能拆开。这些是使用时要记住的边界。

## 7. 从函数入口看代码

```text
detect_dtmf(path)
  ├─ read_wav(path)              读文件、转成浮点音频
  ├─ validate_input(samples, sr) 检查样本和采样率
  ├─ detect_key(frame, sr)       每个短窗识别一个键或 None
  │    ├─ rms_level             检查音量
  │    ├─ goertzel_strength     计算八个候选频率
  │    └─ peak_ratio           检查赢家是否突出
  └─ 合并相邻窗口的标签         返回字符串
```

先从 `detect_key` 阅读，再看 `detect_dtmf` 怎样重复调用它，比从第一行一路往下读更容易抓住主线。
