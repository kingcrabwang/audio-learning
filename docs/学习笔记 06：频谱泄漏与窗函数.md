# 学习笔记 06（回顾）：频谱泄漏与窗函数

> 对应实验：`dsp-toolbox/examples/test_window.py`。这是对 DTMF 之前学习任务的回顾；`spectrum.py` 的周期图和 Welch 函数目前尚未实现。

## 为什么一个正弦波会“漏”到旁边

FFT 只看有限长的一段信号，等效于给原信号乘了一个有限长的窗。如果这段正弦波首尾不能无缝接起来，FFT 会把它的能量分到多个频点，这叫**频谱泄漏**。

频点间隔是 `Δf = sr/N`。仓库实验固定采样率 `sr = 8192 Hz`、正弦频率 `1005 Hz`：

| 点数 N | 观察时长 N/sr | 频点间隔 Δf | 1005 Hz 对应的频点号 |
|---:|---:|---:|---:|
| 1024 | 0.125 s | 8 Hz | 125.625 |
| 2048 | 0.250 s | 4 Hz | 251.25 |

频点号都不是整数，因此 1005 Hz 没有正好落在 FFT 的格点上。点数加倍会让格点更密、主瓣在 Hz 轴上变窄，但**不会自动消除泄漏**。

## 三种窗怎样比较

`test_window.py` 比较矩形、Hann 和 Hamming 窗。矩形窗就是全 1：保留原始样本，但边界往往突然截断，旁瓣较高。Hann 和 Hamming 会压低两端样本，减少旁瓣泄漏；代价是主瓣更宽，两个靠得很近的频率可能更难分开。

不能只说“某个窗总是更低”：要先说比较的是**主瓣宽度、第一旁瓣，还是离主峰很远处的旁瓣**。选窗就是在“分开近邻频率”和“看清弱频率、不被强频率的泄漏盖住”之间取舍。

## 实验代码的每一步

```text
signals[n] = sine_wave(1005, sr, n/sr)   先按长度保存两条信号
windows = {名称: 窗数组}                 每条信号配三种窗
myfft(signal * window)                  先逐点加窗，再算频谱
positive = spectrum[:n//2+1]           实数输入只画非负频率
freqs = arange(n//2+1) * sr/n           给每个频点标上 Hz
amplitude = 2*abs(positive)/sum(window) 对窗造成的幅度变化做校正
db = 20*log10(max(amplitude, 1e-12))   转 dB，避免 log(0)
```

脚本用 `(n, name)` 作为字典键，保存每种“点数 × 窗”的曲线；两层绘图循环把它们放进 **2 行 × 3 列**的图。`for name, window in windows.items()` 的意思是同时取出字典的“名称”和“对应数组”。

这里的 `2*...` 适用于图中所看的**正频率内部频点**；如果以后要画直流 `0 Hz` 或奈奎斯特频点 `sr/2` 的精确单边幅度，就不应把那两个端点也乘 2。

## 怎样运行和读图

在 `dsp-toolbox/` 目录运行 `python examples/test_window.py`。脚本保存 `window_matrix.png` 到**当前工作目录**，然后关闭图形窗口；它虽然叫 `test_window.py`，但现在是绘图实验脚本，不是 `tests/` 下的 pytest 测试。

读图先看主峰大致在 1005 Hz，再比较六张图的主瓣宽度与旁边的“尾巴”。不要只比较某一个点的 dB 值，也不要把“峰更尖”和“泄漏更少”当成同一回事。
